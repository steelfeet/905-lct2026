# README.md

# CRM «ИТ Школа РТК» — двунаправленный контроль обучения

## 1. О продукте

CRM-система для контроля и обработки статистических данных по обучению студентов вузов и школ по ИТ-направлениям. Система автоматизирует взаимодействие ИТ Школы РТК с учебными заведениями, ИТ-продуктами и ИТ-программами.

Главное отличие решения — **двунаправленный workflow**. Жизненный цикл взаимодействия управляется не только со стороны менеджера ИТ Школы, но и со стороны конечного пользователя: представителя вуза, преподавателя, а при необходимости — обучающегося. Оба участника видят актуальный статус, могут оставлять обратную связь, прикладывать файлы, подтверждать или отклонять этапы, запрашивать доработку.

## 2. Проблема

В исходном ТЗ описан длинный линейный путь взаимодействия с вузом из 14 шагов. На практике этот путь контролируется в основном внутренним менеджером. Внешняя сторона — вуз — участвует фрагментарно: подтверждает документы, получает материалы, но не управляет статусами и не влияет на ход процесса в едином информационном поле.

Это приводит к:
- потере контекста между менеджером и вузом;
- задержкам в согласовании и подписании;
- отсутствию прозрачной обратной связи;
- сложности объективной оценки востребованности программ;
- ручному сбору статистики.

## 3. Идея решения

Сделать workflow **двусторонним**:

- **Внутренний контур** — менеджер, руководитель, администратор ИТ Школы РТК.
- **Внешний контур** — представитель вуза, преподаватель, при необходимости обучающийся.

Каждый шаг workflow имеет сторону ответственности:
- `internal` — действие выполняет только ИТ Школа;
- `external` — действие выполняет только вуз/преподаватель;
- `both` — шаг требует совместного участия и/или подтверждения.

Статус шага может находиться в состояниях:
- `pending` — ожидает начала;
- `in_progress` — в работе;
- `waiting_internal` — ожидает действия ИТ Школы;
- `waiting_external` — ожидает действия вуза;
- `approved` — подтверждён;
- `rejected` — отклонён;
- `needs_revision` — требуется доработка;
- `completed` — завершён;
- `cancelled` — отменён.

Обратная связь встроена в каждый шаг: комментарии, файлы, оценка, запрос доработки. История изменений фиксируется в аудите.

## 4. Роли

| Роль | Контур | Основные права |
|---|---|---|
| Пользователь / NAM | Внутренний | Работа с закреплёнными вузами, статусами, комментариями, отчётами |
| Руководитель | Внутренний | Всё, что пользователь + назначение ответственных, изменение ответственных за вузы |
| Администратор | Внутренний | Управление правами, настройками, справочниками, интеграциями |
| Представитель вуза | Внешний | Подтверждение этапов, комментарии, файлы, запрос доработки |
| Преподаватель | Внешний | Обратная связь по обучению, материалам, внедрению |
| Обучающийся | Внешний, ограниченно | Обратная связь по программе, при наличии включённой функции |

## 5. Ключевые возможности

- Двунаправленный workflow по каждому взаимодействию «вуз + ИТ-программа + ИТ-продукт».
- Визуализация пути взаимодействия в виде канбана/таймлайна/диаграммы.
- Переходы между статусами с комментариями и вложениями.
- Корректировка и создание новых workflow.
- Импорт справочников из XLS/XLSX.
- Фильтрация по вузам, ИТ-направлениям, ИТ-продуктам, ответственным, периодам.
- Отчёты в XLS, XLSX, PDF.
- Диаграммы и графики: PNG, PDF.
- Интеграция по API с LMS и сайтом на Laravel.
- Авторизация через Keycloak.
- Ролевая модель и разграничение доступа к данным.
- Кэширование действий и справочников.
- Аудит действий.
- Адаптивный интерфейс для десктопа и мобильных устройств.

## 6. Архитектура

### Компоненты

1. **Web UI** — Vanilla JS SPA.
2. **API Backend** — PHP 8.3 + Laravel 11.
3. **Auth** — Keycloak, OIDC, JWT.
4. **DB** — PostgreSQL 16.
5. **Cache/Queue** — Redis 7.
6. **File Storage** — локальное хранилище или S3-совместимое.
7. **Report Service** — очередь + PhpSpreadsheet + Dompdf.
8. **Integration Service** — LMS, сайт Laravel.
9. **Swagger/OpenAPI** — документация API.
10. **Docker Compose** — php-fpm, nginx, postgres, redis, keycloak, worker.

### Стек

- Backend: PHP 8.3, Laravel 11.
- Frontend: Vanilla JS, HTML5, CSS3, Chart.js для графиков.
- БД: PostgreSQL.
- Кэш/очереди: Redis.
- Auth: Keycloak.
- Отчёты: PhpSpreadsheet, Dompdf/TCPDF.
- Документация API: OpenAPI/Swagger.
- Контейнеризация: Docker, Docker Compose.
- ОС: Linux.

## 8. Интеграции

- **LMS ИТ Школы РТК** — получение данных по обучению, потокам, студентам, статусам.

- **API-контракты** — JSON, согласованные поля, возможность добавления в существующий или новый workflow.

## 9. Отчёты и визуализация
